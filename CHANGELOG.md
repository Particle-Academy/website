# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]
### Added
- **CI** (`.github/workflows/ci.yml`): the org's third-party dependency allowlist gate, plus type-check, both Vite bundles and the Pest suite on every push to `main` and every pull request. The site previously had no workflows, so nothing checked any of it.
- **Pint style check in CI** (`vendor/bin/pint --test`, after the tests). Pint was already a dev dependency but nothing ran it, and eleven PHP files had drifted; they were formatted in a commit of their own.
- **No MCP secret files** (`.github/workflows/no-mcp-secrets.yml`): rejects a push or pull request that tracks an `mcp.json` config, which routinely holds API tokens.
- **`Database\Factories\Support\FakeData`**, first-party fake data for factories and seeders, copied byte for byte from the Fancy UI starter kit (1.1.47) along with its test. `UserFactory` uses `FakeData::shared()->name()` and `FakeData::shared()->unique()->safeEmail()` where it used `fake()`. It covers only those formatters, repeats its sequence when seeded, and its `unique()` throws once it runs out of values, as Faker's does.

### Changed
- **`@particle-academy/react-fancy` 5.15.0 → 5.26.0.** The one breaking entry in that span is 5.17.0's "`Field` no longer spaces itself"; every place this site stacks two or more `Field`s already sits in a `space-y-4` form or a `grid gap-4` row, so no markup changed. It also fixes the admin modals: the right-hand field of each two-column row (Role, Rating, Display order) had been sitting 16px below its neighbour, which is exactly the defect 5.17.0 describes. Measured in a browser before and after. The update also drops `clsx` from the installed tree (5.22.0 inlined it).
- **Retired `Action` alias replaced with `Button`** in all 28 places it was still rendered: the three admin CRUD pages (page actions, form modals, delete confirmations, the waiting-list interest tags) and the three microsites. `Action` is the same component under its old name, kept by react-fancy only as a deprecated alias a future major removes, so no prop changed. Verified in a browser: the outerHTML of every rendered button, admin modals included, is byte-identical before and after. A source-contract test now fails if a page imports `Action`, `ActionColor` or `ActionProps` from react-fancy, or renders `<Action>`.
- **Every dependency moved to its latest release (2026-11-01).** Majors, each taken because the build, the type-check and the suite cover it and none needed a code change:
  - **`vite` 6.4.3 → 8.3.5**, with the two plugins that pin it: **`@vitejs/plugin-react` 4.7.0 → 6.1.2** and **`laravel-vite-plugin` 1.3.0 → 3.2.0**. `vite.config.js` is unchanged. Vite 8 bundles with Rolldown instead of Rollup + esbuild, and plugin-react 6 transforms with Oxc instead of Babel, so the whole Babel / esbuild / Rollup / browserslist subtree has left the install (46 packages removed, 6 added). The client bundle is smaller (assets 1718 KB → 1486 KB; the `lucide-react` chunk 813 KB → 563 KB). The "chunk larger than 500 kB" warning was already there on Vite 6 and still is.
  - **`typescript` 6.0.3 → 7.0.2**, the native compiler. `tsconfig.json` is unchanged and `tsc --noEmit` passes; a deliberately mistyped file was confirmed to fail it, so the check still checks.
  - **`pestphp/pest` 4.7.0 → 5.3.5**, which brings **PHPUnit 12.5 → 13.4** and the Pest 5 plugins. No test changed; all 39 pass.
  - Transitive majors pulled in by `composer update -W`, none called directly by this app: `guzzlehttp/guzzle` 7 → 8 (with `psr7` 3, `promises` 3), `brick/math` 0.14 → 1.0, `laravel/mcp` 0.7 → 1.1 and `laravel/roster` 0.5 → 1.0 (both through `laravel/boost`), `hamcrest/hamcrest-php` 2 → 3 (through `mockery`).
  - First-party: **`@particle-academy/react-fancy` 5.26.0 → 5.72.0**, **`@particle-academy/fancy-inertia` 0.11.0 → 0.14.0** and **`@particle-academy/fancy-query` 0.8.0 → 0.9.1**. The two 0.x ranges are now `>=0.14.0 <2.0` and `>=0.9.1 <2.0`: a caret on a 0.x locks the minor, which is why both had sat behind. fancy-inertia 0.14 adds `@particle-academy/fancy-app-update` as a dependency of its own.
  - Minor and patch: `@inertiajs/react` 3.10.0, `@tanstack/react-query` 5.105.1, `react` / `react-dom` 19.3.1, `tailwindcss` / `@tailwindcss/vite` 4.3.3, `@types/*`, `concurrently` 10.0.6; `laravel/framework` 13.39.0, `inertiajs/inertia-laravel` 3.6.0, `laravel/boost` 2.10.4, `laravel/pint` 1.32.1, `laravel/sail` 1.69.0, `mockery/mockery` 1.6.15, `nunomaduro/collision` 8.9.5. Composer floors were raised to the installed versions.
- **Icons render through react-fancy's `<Icon name="...">`** in all 14 files that imported `lucide-react` directly (64 `<Icon>` call sites, 50 distinct icons). `lucide-react` was never a dependency of this site; it only resolved because npm hoisted react-fancy's copy, so it could have broken or changed version under any react-fancy release. Every icon keeps its glyph, size, colour, stroke width and fill: measured in a browser on the seven public pages and the four admin pages before and after, and every rendered svg matches. Sizes that are not an `<Icon>` preset (the 14px badge icons on two microsites, and the icons the home stylesheet sizes) size the wrapper as well as the svg, so nothing shifts while the icon set loads. A source-contract test fails if a TS/TSX file imports `lucide-react` again or if `package.json` declares it.
- **`vite.config.js` keeps `lucide-react` in a chunk of its own.** `<Icon>` resolves names against the whole Lucide namespace, so every icon ships whichever ones the site uses; without the group Rolldown folded those 562 KB into the app entry, which changes on every deploy. The weight itself belongs to react-fancy and cannot shrink from this side.

### Removed
- **AOS (Animate On Scroll), which was hot-linked from unpkg** (`aos@2.3.4`: a stylesheet in the head and a script plus `AOS.init` before `</body>`). It animated nothing: the last `data-aos` attribute went with the old home sections in the Civicognita rebuild, and no page, layout or view has one, so every visitor downloaded and ran a third-party script from a CDN that no lockfile, allowlist or audit could see. AOS's CSS only targets `[data-aos]`, so removing it changes no rendering; checked in a browser with motion allowed and with `prefers-reduced-motion: reduce`, and the pages now request nothing from a package CDN. There was no reveal effect left to reproduce, so nothing replaces it. A feature test fails if a Blade view or the rendered page references unpkg, jsDelivr, cdnjs, esm.sh, Skypack or JSPM.
- **`fakerphp/faker`**, and the `faker_locale` / `APP_FAKER_LOCALE` setting nothing else read. Its last release and last commit were both on 2026-02-04, which fails the allowlist's three-month freshness bar, and from 2026-09-19 that fails CI. Laravel only defines `fake()` when Faker is installed, so with it gone and the factory unchanged `AdminUserSeederTest` failed with "Call to undefined function `Database\Factories\fake()`". Write `FakeData::shared()->…` in a factory where the Laravel docs write `fake()->…`.
- **The temporary `/_inertia-test` route** and `resources/js/Pages/Test.tsx`, the demo page it rendered. It was a Phase 0 plumbing check from the Inertia migration, marked "TEMP — delete once another page has been migrated", and it stayed publicly reachable long after every page had been. A feature test now asserts the URL 404s and the page component stays gone.
- **Ziggy** (`tightenco/ziggy`) and the `@routes` directive in `resources/views/app.blade.php`. Nothing read it: every page builds its URLs as literal paths (`form.post("/waiting-list")`, `router.delete(\`/admin/partners/${id}\`)`), no TS/TSX calls `route()`, neither built bundle mentions `Ziggy`, and `HandleInertiaRequests::share` has no `ziggy` key. The only `route()` calls left are Laravel's own PHP helper in `AuthenticatedSessionController`. The directive was not harmless, either: it printed every route name and URI into each public page, including the whole `admin.*` group. It was also an unapproved third-party dependency, which failed the allowlist job.

### Fixed
- **Two icon-only admin buttons had no accessible name**: the modal close button now reads "Close", and the mobile menu toggle reads "Open menu" / "Close menu" and reports `aria-expanded`. Their only content was an unlabelled svg, so a screen reader announced them as "button".
- **The Geist typeface never loaded, so the whole site rendered in the system font.** `design-tokens.css` requested it with an `@import url(...)` below its opening comment, and once Tailwind inlines that file the import is no longer the first rule, which CSS ignores; the build dropped it with an "`@import` rules must precede all rules" warning. Geist and Geist Mono now load from a `<link>` in `resources/views/app.blade.php`, next to the existing `preconnect`s, and the unused Instrument Sans stylesheet that link used to fetch is gone (no CSS referenced it). Checked in a browser on the home page: before, no Geist `FontFace` existed and text measured identically to the fallback; after, Geist 400/500/600 and Geist Mono 400/600 load from fonts.gstatic.com and headings measure differently from both fallbacks. Expect slightly different line breaks: the home lede now wraps to three lines instead of four. A feature test asserts the `<link>` is in the head and that no stylesheet under `resources/css` `@import`s a remote URL.

### Security
- **The admin seeder no longer contains a password.** `AdminUserSeeder` created the administrator with an email and password typed into the file, in this public repository, since 2025-04-14; anyone who read it could sign in to any deployment seeded with it. The credentials now come from `ADMIN_EMAIL` / `ADMIN_PASSWORD` (`config/admin.php`) with no defaults. Seeding production without both throws before anything is written; outside production an unset password becomes a random one the seeder prints. **Removing the literal does not un-publish it:** it stays readable in the git history, so any account that was ever given that password must have it changed. A test fails if any seeder hashes or assigns a password literal again.
- **`league/commonmark` 2.9.1 → 2.10.1** (GHSA-8rr7-cvq3-gmfh, high: denial of service through distinctly-named attributes in the Attributes extension). It arrives through `laravel/framework`, whose `^2.8.1` already allowed the fix, so only the lockfile moved.
- **`browserslist` 4.28.2 → 4.28.9** (GHSA-73wf-gq98-2v4g, high) and **`baseline-browser-mapping` 2.10.32 → 2.11.23** (GHSA-w5vr-8v7q-w6rv, medium). Both are build-time only, pulled in by `@vitejs/plugin-react` through Babel, and both fixes sat inside the existing ranges. The regenerated lockfile also lists the other platforms' optional `esbuild` / `rollup` binaries that the previous one had dropped, so `npm ci` resolves the same tree on every OS.
- **`shell-quote` 1.9.0 → 1.12.0** (GHSA-pqg4-j6r4-53mv, critical: `quote()` command injection through a line terminator after a comment token) and **`source-map-js` 1.2.1 → 1.2.2** (GHSA-68fv-2mgg-jv7q, high: event-loop denial of service through indexed source-map section offsets). Both are dev-only. `concurrently` pins `shell-quote` to an exact version, so the fix came from moving `concurrently` 10.0.4 → 10.0.6, which is inside the existing `^10.0.4`. `source-map-js` arrives through `postcss` and `@tailwindcss/node`, whose `^1.2.1` already allowed the fix. Only the lockfile moved.
- **`vite` 6.4.3 → 8.3.5** clears the five advisories against `vite <=6.4.3`, all in the dev server: three in its bundled `launch-editor` (GHSA-698v-4r3x-3vcv, GHSA-r825-w8mm-5pxw, GHSA-587h-7wmj-h5pm), cross-origin script execution through custom middleware (GHSA-9jrq-w75r-8gcw), and files outside `server.fs.allow` being served (GHSA-rq7h-c2jc-7f22). Production serves the built assets and never runs the dev server, so this protected the machines of people working on the site rather than the site.
- **`symfony/http-foundation` 8.1.0 → 8.1.10** (CVE-2026-108082, high: ReDoS in `HeaderUtils::split()` through the `Cache-Control` request header; this one IS reachable by any visitor), **`symfony/yaml` 8.0.13 → 8.1.10** (CVE-2026-109413, high: unbounded recursion in the inline lexer) and **`symfony/mime` 8.0.13 → 8.1.10** (CVE-2026-45070, medium: email header injection through mime parameter names). All three arrive through `laravel/framework`. `npm audit` and `composer audit` both report nothing after this change.
